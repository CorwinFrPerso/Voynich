# Session Guillaume + ChatGPT, août 2026

Ce fichier conserve les idées, observations et décisions issues de la session de travail. Il ne prétend pas être une transcription diplomatique mot à mot du chat ; il en conserve le contenu de recherche utile.

## 1. Point de départ : translittération

Guillaume pose le problème central :

- EVA aplatit potentiellement des distinctions graphiques importantes ;
- v101 est beaucoup plus fidèle visuellement, mais peut fragmenter excessivement les catégories ;
- le système pourrait être une traduction/sténographie mnémotechnique complexe mais uniforme fondée sur traits, boucles, hampes et combinaisons ;
- les anomalies sont à utiliser pour remonter à la logique du système.

Décision : conserver simultanément image originale, v101, EVA et une couche propre de primitives.

## 2. Font v101

Hypothèse : utiliser la font v101 comme modèle géométrique idéal pour analyser familles de formes, rails, boucles, hampes et ressemblances.

Limite reconnue : une font ne donne ni ordre réel des coups de plume ni segmentation certaine. Elle ne remplace jamais les scans.

## 3. Décomposition paléographique de Guillaume

Guillaume décrit explicitement les EVA comme constructions graphiques, notamment :

- `e = c` ;
- `a = c + i` agglutinés ;
- `n = i + boucle montante depuis le bas` ;
- `m = i + bouclette droite` ;
- `p = f + boucle gauche` ;
- `t = k + boucle gauche` ;
- `ch` visuellement comme `cc` reliés par un rail ;
- `sh` comme le même ensemble avec une marque/bouclette supplémentaire ;
- plusieurs caractères EVA sont donc des conventions ASCII potentiellement trompeuses.

Cette cartographie complète est conservée dans `01_PALEOGRAPHIE_EVA.md`.

## 4. Humilité méthodologique

Guillaume insiste : 600 ans d'échecs doivent rendre humble.

Danger identifié : sur-analyser les micro-variations d'un manuscrit vieux de six siècles avec vision HD moderne.

Décision commune :

> coarse first, fine only when forced.

Une distinction doit être visible et utile à un lecteur historique avant d'être supposée fonctionnelle.

## 5. Gallows

Observation structurale forte :

```text
p = f + boucle gauche
t = k + boucle gauche
```

Cela ressemble à un système combinatoire plutôt qu'à quatre lettres indépendantes.

Décision : tester les transformations comme opérateurs et comparer leur effet contextuel.

## 6. Rails / benches

Correction importante apportée par Guillaume :

- le rail n'est pas partout ;
- il faut distinguer `cc + rail` des formes `c + gallow + c` avec rail global ;
- dans ces dernières, le rail porté par les c peut couper/intersecter les jambes des gallows.

Décision : ne plus parler du rail comme d'un opérateur générique sans préciser sa construction locale.

## 7. f8r et les formes longues

Guillaume signale sur f8r une structure rare : deux chunks semblent reliés par une forme ressemblant à un gallow à deux branches.

Observation de travail :

- branche gauche sur une structure de type `cc + rail + o` ;
- branche droite sur une structure de type `cc + rail + c + g` ;
- ambiguïté : vrai gallow atomique ou composition de traits et boucles qui ressemble à un gallow ?

Nouvelle hypothèse : certains longs gallows pourraient être des **opérateurs de portée** ou de factorisation, appliquant une information commune à plusieurs chunks.

Conséquence possible : certains espaces graphiques ne correspondent pas nécessairement à des frontières lexicales du texte clair.

## 8. q et qo

Guillaume rappelle une propriété structurante : EVA-q apparaît presque toujours en début de mot/groupe et est souvent suivi de o.

Décision : considérer `q` et surtout `qo` comme candidats à une fonction de préfixe, classe, macro ou opcode avant toute correspondance phonétique lettre à lettre.

## 9. Modèle vocalique

Question : que faire si les voyelles sont mélangées ou codées indirectement ?

Modèles retenus :

- alphabet plat ;
- alphabet featural ;
- base consonantique + opérateur vocalique ;
- syllabaire/morphographie ;
- système hybride avec abréviations.

Décision : ne pas choisir par intuition. Faire gagner le modèle par prédiction et compression.

## 10. Allemand + latin

Intuition de Guillaume : mélange d'un allemand historique non encore déterminé et de latin.

Cadre retenu comme candidat : vernaculaire germanique du XVe siècle + latin médical/technique + conventions d'abréviation communes.

Cette hypothèse reste volontairement secondaire tant qu'aucune fonction graphique stable ou aucun crib n'est trouvé.

## 11. Simulation mentale d'un système humain

Question posée : quelles règles simples, humaines et légèrement tordues pourraient transformer des phrases médico-astrologiques médiévales en formes Voynich ?

Modèles envisagés :

1. sténographie morphographique ;
2. syllabaire featural ;
3. codage hybride phonétique + opérateurs sémantiques ;
4. factorisation d'une instruction ou quantité commune sur plusieurs éléments.

Formules tests utilisées uniquement comme modèles conceptuels, jamais comme lectures :

- `Contra febrem` ;
- `Ad dolorem capitis` ;
- `Recipe X et Y, ana ...`.

Conclusion : il est facile de produire les contraintes visuelles du Voynich avec peu de règles mnémotechniques, ce qui augmente le risque de sur-ajustement.

## 12. Le problème existentiel : explosion des hypothèses

Guillaume identifie le risque principal :

> sans contrainte externe, nous allons revivre des centaines de bonnes et fausses pistes puis échouer ou abandonner.

Décision majeure : passer à une stratégie **CRIB FIRST**.

## 13. Inversion du crib

Nouvelle stratégie :

```text
image / ordre / structure documentaire
        ↓
source médiévale apparentée
        ↓
texte associé
        ↓
crib
        ↓
reconstruction du système Voynich
```

Plutôt que :

```text
Voynich -> lettres -> mots -> langue -> source
```

## 14. Herbal A comme premier terrain

Idée principale : ne surtout pas chercher une plante isolée.

Chercher une séquence :

```text
Voynich A -> source plante n
Voynich B -> source plante n+1
Voynich C -> source plante n+2
```

Une correspondance séquentielle multi-page est beaucoup plus discriminante qu'une identification botanique unique.

Approche prévue : vision grossière + ordre des plantes + alignement de séquences + corpus négatif + validation prospective.

## 15. Autres terrains de crib

- astro-médecine ;
- régimes de santé ;
- saignée ;
- balnéologie ;
- pharmacopées et recettes ;
- sources mixtes latin/vernaculaire.

La section balnéologique peut être particulièrement intéressante si elle dérive d'une tradition documentaire plus étroite que l'herbier.

## 16. Algorithmes envisagés

Pour la chasse au crib :

- embeddings visuels comme générateurs de candidats, pas comme juge final ;
- similarité de séquence ;
- Smith-Waterman local ;
- dynamic time warping ;
- HMM ;
- alignement avec gaps ;
- tests par permutation ;
- corpus négatifs ;
- mise à jour bayésienne ;
- validation hors échantillon.

## 17. Principe anti-fausse-piste

Un candidat n'est retenu que s'il permet une prédiction prospective.

Exemple : utiliser trois images Voynich pour identifier une source, puis prédire la quatrième sans l'avoir utilisée.

## 18. État actuel de la recherche

Priorités :

1. trouver un crib documentaire ;
2. préserver une couche paléographique robuste ;
3. utiliser les gallows, q/qo et formes longues seulement pour tester le crib ou départager les mécanismes ;
4. ne revenir à la langue qu'après réduction massive de l'espace des possibilités.

## 19. Formulation la plus importante de la session

> Ne plus chercher d'abord à deviner ce que dit le Voynich. Chercher le document, la tradition ou le texte qu'il pourrait compresser, adapter ou recopier.

C'est désormais la direction principale du projet.
